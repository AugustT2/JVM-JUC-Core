指令重排与有序性 happens-before
线程 1
/* 写线程 */
int x = 0;
boolean ready;
线程 2
/* 读线程 */
if (ready) {
    use(x);
}
无 volatile: 可能的重排
1 线程 1 将 ready 赋值 true 的写重排到 x = 1 之前
2 线程 2 先读到 ready == true, 再读取 x, 可能仍为 0
3 出现 ready 为 true 但 x 还是旧值的情况
有 volatile: 重排被禁止
1 对 volatile ready 的写之前的 x = 1 被禁止重排到后面
2 线程 2 读取 volatile ready 为 true 时, 必须先读取内存中最新的 x
3 保证看到 ready 为 true 时一定也能看到 x = 1
可见性: 缓存与主内存同步
有序性: 写入与读取的先后关系
volatile 如何保证可见性
  • 对 volatile 变量的写在底层会转换为带有内存屏障的写入, 写入后会把该变量刷新到主内存。
  • 对 volatile 变量的读会从主内存中重新读取该变量, 同时使本地缓存中对应的缓存行失效。
  • 在 Java 内存模型中, volatile 写对后续任意线程的 volatile 读建立了 happens-before 关系。
volatile 如何影响有序性
  • 对 volatile 变量的写, 禁止其前面的普通读写被重排到后面。
  • 对 volatile 变量的读, 禁止其后面的普通读写被重排到前面。
  • 结合这两条, 可构建出类似轻量级锁的“发布-订阅”模式, 保证对象发布的安全性。
volatile 与 synchronized 的区别
  • volatile 只保证可见性和一定的有序性, 不提供原子性和互斥, 适合状态标志、配置开关等简单场景。
  • synchronized 除了可见性和有序性外, 还通过锁保证临界区代码的互斥执行, 能维护复合操作的原子性。
  • 可视化上可以理解为: volatile 只在变量旁边加了“广播更新”的喇叭, 而 synchronized 还在代码块入口加了一道“同一时刻只允许一个线程进入”的门。
