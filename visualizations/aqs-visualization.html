什么是 AQS？

AQS（AbstractQueuedSynchronizer）是 Java 并发包 java.util.concurrent 的核心基础框架，用于构建锁和同步器。

它通过一个 volatile int state 变量来表示同步状态，通过内置的 FIFO 队列（CLH变体） 来管理等待获取资源的线程。

常见的 ReentrantLock、Semaphore、CountDownLatch、ReentrantReadWriteLock 都是基于 AQS 实现的。

1 核心思想

如果请求的共享资源空闲，则将当前线程设置为有效工作线程，并将资源设为锁定状态；如果资源被占用，则需要一套线程阻塞等待及唤醒机制。

2 设计模式

采用模板方法模式，子类只需实现 tryAcquire、tryRelease 等方法，其他复杂的排队、阻塞、唤醒由 AQS 统一处理。

3 两种模式

独占模式：只有一个线程能执行（如ReentrantLock）；共享模式：多个线程可同时执行（如Semaphore）。

CLH 队列详解

CLH（Craig, Landin, and Hagersten）队列是一个虚拟的双向队列（FIFO），AQS 将等待获取锁的线程封装成 Node 节点加入队列。

static final class Node { // 等待状态 volatile int waitStatus; // 前驱节点 volatile Node prev; // 后继节点 volatile Node next; // 入队的线程 volatile Thread thread; // 等待状态常量 static final int CANCELLED = 1; // 取消 static final int SIGNAL = -1; // 需唤醒后继 static final int CONDITION = -2; // 条件等待 static final int PROPAGATE = -3; // 共享传播 }

关键点：

• head 指向队列头部（通常是持有锁的节点或哨兵节点）

• tail 指向队列尾部（最后加入的等待节点）

• 入队操作使用 CAS + 自旋 保证线程安全

State 状态变量

state 是 AQS 的核心状态变量，使用 volatile 保证可见性，通过 CAS 操作保证原子性。

// state 变量定义 private volatile int state; // 获取状态 protected final int getState() { return state; } // 设置状态 protected final void setState(int newState) { state = newState; } // CAS 修改状态（原子操作） protected final boolean compareAndSetState(int expect, int update) { return U.compareAndSetInt(this, STATE, expect, update); }

不同锁中 state 的含义：

• ReentrantLock：0 表示未锁定，≥1 表示锁定（值为重入次数）

• Semaphore：表示可用的许可数量

• CountDownLatch：表示需要等待的计数

• ReentrantReadWriteLock：高16位为读锁计数，低16位为写锁计数

public final void acquireShared(int arg) { // tryAcquireShared 返回值 < 0 表示获取失败 if (tryAcquireShared(arg) < 0) doAcquireShared(arg); } // 共享模式下释放后会传播唤醒 private void doAcquireShared(int arg) { final Node node = addWaiter(Node.SHARED); for (;;) { final Node p = node.predecessor(); if (p == head) { int r = tryAcquireShared(arg); if (r >= 0) { // 设置头节点并传播唤醒后续共享节点 setHeadAndPropagate(node, r); return; } } parkAndCheckInterrupt(); } }

共享模式的传播机制：当一个共享节点获取到资源后，如果还有剩余资源，会唤醒后续的共享节点，形成连锁唤醒效果。

Condition 条件队列

Condition 是 AQS 内部类 ConditionObject 的实例，用于实现类似 Object.wait/notify 的功能。

public final void await() { // 1. 将当前线程封装成 Node 加入条件队列 Node node = addConditionWaiter(); // 2. 完全释放锁（支持重入） int savedState = fullyRelease(node); // 3. 在条件队列中等待，直到被 signal while (!isOnSyncQueue(node)) { LockSupport.park(this); } // 4. 被唤醒后，重新竞争锁 acquireQueued(node, savedState); } public final void signal() { // 将条件队列的第一个节点转移到同步队列 Node first = firstWaiter; if (first != null) doSignal(first); }

核心流程：

• await()：释放锁 → 加入条件队列 → 阻塞等待

• signal()：将节点从条件队列转移到同步队列 → 等待获取锁

Q1 AQS 的核心原理是什么？

AQS 通过一个 volatile int state 变量和一个 FIFO 等待队列来管理同步状态。state 表示资源的占用状态，队列存放等待获取资源的线程。获取资源时先尝试 CAS 修改 state，失败则入队等待；释放资源时修改 state 并唤醒队列中的等待线程。

Q2 独占模式和共享模式的区别？

独占模式：同一时刻只能有一个线程获取资源（如 ReentrantLock）。共享模式：同一时刻可以有多个线程获取资源（如 Semaphore、CountDownLatch）。主要区别在于 tryAcquire vs tryAcquireShared 的实现，以及共享模式有传播唤醒机制。

Q3 CLH 队列的特点？

CLH 队列是一个虚拟的双向队列，通过 prev/next 指针连接 Node 节点。入队使用 CAS+自旋 保证线程安全，出队只需修改 head 指针。每个节点有 waitStatus 状态：SIGNAL(-1) 表示后继需要被唤醒，CANCELLED(1) 表示取消等待。

Q4 为什么用 CAS + volatile？

volatile 保证 state 的可见性，多线程读取时能获取最新值。CAS 保证 state 修改的原子性，避免使用重量级锁。这种组合被称为"无锁编程"，性能高于 synchronized。

Q5 ReentrantLock 如何实现可重入？

每次获取锁时检查当前线程是否是锁的持有者（exclusiveOwnerThread），如果是则 state+1 而非竞争锁；释放锁时 state-1，只有当 state=0 时才真正释放锁并唤醒其他线程。

Q6 Condition 和 Object.wait 的区别？

• Condition 可以创建多个等待队列，Object 只有一个
• Condition 支持不响应中断的等待
• Condition 必须配合 Lock 使用，更灵活
• Condition 支持指定唤醒某个队列的线程

Q7 公平锁与非公平锁的实现区别？

非公平锁：新来的线程直接尝试 CAS 获取锁，失败才入队。公平锁：新来的线程先检查队列是否有等待者（hasQueuedPredecessors），有则直接入队等待。非公平锁性能更好（减少线程切换），公平锁避免饥饿。

Q8 AQS 用到了哪些设计模式？

模板方法模式：acquire/release 定义了算法骨架，tryAcquire/tryRelease 由子类实现具体逻辑。这样子类只需关注同步语义的实现，队列管理、线程阻塞等复杂操作由 AQS 统一处理。
