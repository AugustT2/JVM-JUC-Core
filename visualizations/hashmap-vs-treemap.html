底层结构对比

🗂️ HashMap 底层结构

  • 数组 + 链表 + 红黑树（JDK 8+）
  • 底层是一个 Node[] table 数组
  • 每个数组位置称为一个"桶"（bucket）
  • 通过 hash(key) % capacity 决定放入哪个桶
  • 哈希冲突时，新节点挂到链表尾部
  • 链表长度 ≥ 8 且数组长度 ≥ 64 时，链表转为红黑树
  • 负载因子默认 0.75，超过时扩容为 2 倍

🌳 TreeMap 底层结构

  • 底层是一棵红黑树（Red-Black Tree）
  • 每个节点存储 key-value 对
  • 按 key 的自然顺序（或 Comparator）排列
  • 通过比较 key 大小决定左/右子树
  • 插入后通过旋转和变色维持平衡
  • 树高始终 ≤ 2·log₂(n+1)
  • 中序遍历即为有序序列

TreeMap 如何保证有序？

🌳 红黑树的中序遍历 = 有序序列

TreeMap 的有序性来源于红黑树的二叉搜索树性质 + 中序遍历。整个过程分为两步：

第一步：BST 性质保证结构有序

  • • 插入时，通过 compareTo(key) 比较大小
  • • key 比当前节点小 → 放入左子树
  • • key 比当前节点大 → 放入右子树
  • • 这保证了：左 < 根 < 右

第二步：中序遍历输出有序序列

  • • 中序遍历顺序：左 → 根 → 右
  • • 因为 左 < 根 < 右，所以输出天然有序
  • • 红黑树的平衡性保证遍历效率 O(n)
  • • iterator()、entrySet() 等都基于中序遍历

🔄 插入流程示意

put("banana", 2)
→
compareTo("apple") > 0
→
走右子树
→
compareTo("cherry") < 0
→
走左子树
→
插入 + 旋转修复

⚠️ 注意事项

  • • Key 必须实现 Comparable 接口，或在构造时传入 Comparator
  • • Key 的比较逻辑必须与 equals() 一致，否则行为异常
  • • HashMap 用 equals() 判断相等，TreeMap 用 compareTo() 判断相等
  • • TreeMap 不允许 null key（因为无法比较），HashMap 允许一个 null key

HashMap 的 Put 流程

🗂️ 从 Key 到桶位置

put(key, val)
→
hash(key)
→
index = hash & (n-1)
→
放入桶[index]
例： "hello" .hashCode() = 69609650 → 扰动 69609650 ^ (69609650 >>> 16) → index = hash & 15 = 2

JDK 8 使用 hash ^ (hash >>> 16) 做扰动处理，让高位也参与运算，减少碰撞概率。 数组长度必须是 2 的幂次，这样 hash & (n-1) 等价于取模运算，但更快。

使用场景对比

🗂️ 适合用 HashMap

  • 只需要快速查找，不关心顺序
  • 频繁的 put/get 操作，追求 O(1) 性能
  • 缓存、计数器、索引映射
  • Key 可以是 null
  • 大部分业务场景的默认选择

🌳 适合用 TreeMap

  • 需要 key 按顺序排列
  • 需要范围查询（如查找某个区间的 key）
  • 需要快速获取最小/最大 key
  • 需要排序的 Map输出
  • 排行榜、区间统计、滑动窗口

HashMap：追求速度，O(1) 查找，但无序  |  TreeMap：追求有序，O(log n) 查找，支持范围操作
