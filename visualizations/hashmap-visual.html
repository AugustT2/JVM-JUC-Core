数据结构说明

HashMap 底层采用 数组 + 链表 + 红黑树 的混合结构：

// Node数组，存储键值对
Node<K,V>[] table;

// Node节点结构
static class Node<K,V> {
  final int hash;
  final K key;
  V value;
  Node<K,V> next; // 链表指针
}

当链表长度 ≥ 8 且数组长度 ≥ 64 时，链表转换为红黑树，提高查询效率从 O(n) 到 O(log n)。

📝 面试要点

  • 为什么用数组+链表+红黑树？兼顾空间和时间效率
  • 默认初始容量16，必须是2的幂次（位运算优化）
  • 负载因子0.75是时间和空间的折中
  • JDK8之前只有数组+链表，JDK8引入红黑树优化

// 扰动函数 - 让高位也参与运算，减少碰撞
static final int hash(Object key) {
  int h;
  return (key == null) ? 0 : (h = key.hashCode()) ^ (h >>> 16);
}

// 计算数组下标 (n是数组长度)
index = (n - 1) & hash; // 等价于 hash % n，但位运算更快

Hash计算过程

1. 获取hashCode：调用key的hashCode()方法

2. 扰动函数：h ^ (h >>> 16)，将高16位与低16位异或，让哈希分布更均匀

3. 取模运算：(n-1) & hash，用位运算代替取模，效率更高

// 为什么 (n-1) & hash 等价于 hash % n？
// 因为n是2的幂次，n-1的二进制全是1
// 例如：n=16, n-1=15=0b1111
// hash & 0b1111 就是取hash的后4位，等价于 hash % 16

📝 面试要点

  • 为什么要用扰动函数？减少哈希碰撞，让分布更均匀
  • 为什么容量必须是2的幂？(n-1)&hash 位运算代替取模，效率更高
  • hashCode()返回int，32位；扰动函数让高16位也参与运算
  • String的hashCode：s[0]*31^(n-1) + s[1]*31^(n-2) + ... + s[n-1]

Put 流程详解

public V put(K key, V value) {
  // 1. 计算hash
  return putVal(hash(key), key, value, false, true);
}

final V putVal(int hash, K key, V value, ...) {
  // 2. 判断数组是否为空，为空则初始化
  if (table == null) resize();

  // 3. 计算下标，判断该位置是否为空
  if ((p = tab[i = (n-1) & hash]) == null)
    tab[i] = newNode(hash, key, value, null);
  else {
    // 4. 位置不为空，处理冲突
    // - key相同则覆盖
    // - 是树节点则走红黑树插入
    // - 否则遍历链表，尾插法插入
  }

  // 5. 判断是否需要扩容
  if (++size > threshold) resize();
}

📝 面试要点

  • JDK8改为尾插法（JDK7是头插法，多线程会形成环链）
  • 先插入再判断扩容（JDK7是先扩容再插入）
  • key为null时，hash为0，固定存在table[0]
  • put返回旧值，如果是新增则返回null

Get 流程详解

public V get(Object key) {
  Node<K,V> e;
  return (e = getNode(hash(key), key)) == null ? null : e.value;
}

final Node<K,V> getNode(int hash, Object key) {
  // 1. 计算下标，获取头节点
  first = tab[(n - 1) & hash];

  // 2. 判断头节点是否匹配
  if (first.hash == hash && first.key.equals(key))
    return first;

  // 3. 遍历链表或红黑树查找
  if (first instanceof TreeNode)
    return getTreeNode(hash, key); // O(log n)
  else
    // 遍历链表 O(n)
}

📝 面试要点

  • 先比较hash，再比较key（==或equals）
  • 为什么重写equals必须重写hashCode？保证相同对象有相同hash
  • 链表查找O(n)，红黑树查找O(log n)
  • get不存在的key返回null，不会抛异常

扩容机制详解

触发条件：size > capacity * loadFactor (元素数量超过阈值)

final Node<K,V>[] resize() {
  // 1. 容量翻倍
  newCap = oldCap << 1; // 16 → 32
  newThr = oldThr << 1; // 12 → 24

  // 2. 重新计算每个元素的位置
  for (Node<K,V> e : oldTab) {
    // 关键：(e.hash & oldCap) == 0 ?
    // 是 → 位置不变
    // 否 → 位置 = 原位置 + oldCap
  }
}

JDK8优化：不需要重新计算hash，只需判断新增的那一位是0还是1

📝 面试要点

  • 扩容是2倍扩容，保证容量始终是2的幂
  • JDK8优化：e.hash & oldCap 判断新位置，不用重算hash
  • 扩容时机：先插入后扩容（JDK7是先扩容后插入）
  • 多线程扩容可能导致数据丢失（JDK7会形成环链）

树化与退化条件

// 树化条件（两个都要满足）
static final int TREEIFY_THRESHOLD = 8; // 链表长度阈值
static final int MIN_TREEIFY_CAPACITY = 64; // 数组最小容量

// 退化条件
static final int UNTREEIFY_THRESHOLD = 6; // 扩容时树节点≤6则退化

// 树化逻辑
if (binCount >= TREEIFY_THRESHOLD - 1) {
  if (tab.length < MIN_TREEIFY_CAPACITY)
    resize(); // 优先扩容
  else
    treeifyBin(tab, hash); // 转红黑树
}

📝 面试要点

  • 为什么是8？泊松分布，链表长度达到8的概率极低（0.00000006）
  • 为什么要求数组长度≥64？小数组扩容比树化更有效
  • 为什么退化阈值是6不是8？避免频繁树化和退化
  • 红黑树特性：自平衡，查找O(log n)，最长路径≤2倍最短路径
