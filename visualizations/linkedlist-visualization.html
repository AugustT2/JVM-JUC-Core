双向链表结构

LinkedList 基于双向链表实现，每个节点包含三个部分：prev（前驱指针）、item（数据）、next（后继指针）。链表维护 first 和 last 两个指针分别指向头尾节点。

private static class Node<E> {
    E item;          // 存储的数据
    Node<E> next;    // 指向下一个节点
    Node<E> prev;    // 指向上一个节点

    Node(Node<E> prev, E element, Node<E> next) {
        this.item = element;
        this.next = next;
        this.prev = prev;
    }
}

add() 添加元素

LinkedList 的 add() 默认在链表尾部添加元素（linkLast）。也可以指定位置插入，时间复杂度分别是 O(1) 和 O(n)。

// add(E e) - 尾部添加，O(1)
public boolean add(E e) {
    linkLast(e);
    return true;
}

void linkLast(E e) {
    final Node<E> l = last;       // 1. 保存当前尾节点
    final Node<E> newNode = new Node<>(l, e, null);  // 2. 创建新节点
    last = newNode;              // 3. 更新 last 指针
    if (l == null)
        first = newNode;         // 空链表时，first 也指向新节点
    else
        l.next = newNode;        // 4. 原尾节点的 next 指向新节点
    size++;
}

remove() 删除元素

删除操作需要修改前后节点的指针。删除头尾节点 O(1)，删除中间节点需先遍历找到位置 O(n)。

// unlink(Node x) - 断开节点连接
E unlink(Node<E> x) {
    final E element = x.item;
    final Node<E> next = x.next;  // 1. 获取后继节点
    final Node<E> prev = x.prev;  // 2. 获取前驱节点

    if (prev == null) {
        first = next;            // 删除的是头节点
    } else {
        prev.next = next;        // 3. 前驱的 next 指向后继
        x.prev = null;
    }

    if (next == null) {
        last = prev;             // 删除的是尾节点
    } else {
        next.prev = prev;        // 4. 后继的 prev 指向前驱
        x.next = null;
    }

    x.item = null;               // 帮助 GC
    size--;
    return element;
}

LinkedList vs ArrayList

两者都实现了 List 接口，但底层数据结构完全不同。ArrayList 基于动态数组，LinkedList 基于双向链表，适用场景也不同。

ArrayList - 连续内存数组

LinkedList - 分散节点链表

操作 ArrayList LinkedList 原因
随机访问 get(i) O(1) O(n) 数组可直接索引，链表需遍历
尾部添加 add(e) O(1)* O(1) *ArrayList 扩容时 O(n)
中间插入 add(i,e) O(n) O(n) 数组需移动元素，链表需遍历找位置
头部插入 add(0,e) O(n) O(1) 数组需移动所有元素
内存占用 较小 较大 链表每个节点额外存储两个指针
缓存友好性 好 差 数组连续内存，CPU 缓存命中率高

LinkedList 面试高频考点

以下是关于 LinkedList 最常被问到的面试题，掌握这些可以应对绝大多数面试场景。

Q1: 说说 LinkedList 的底层结构？

答：LinkedList 底层是双向链表，每个节点（Node）包含三个字段：item（数据）、prev（前驱指针）、next（后继指针）。链表维护 first 和 last 指针指向头尾。

Q2: LinkedList 和 ArrayList 如何选择？

答： • 频繁随机访问 → ArrayList（O(1) vs O(n)）
• 频繁头部插入删除 → LinkedList
• 大多数场景 → ArrayList（缓存友好，实际性能更好）

Q3: LinkedList 的 add() 真的是 O(1) 吗？

答： • add(e) 尾部添加 → O(1)
• add(index, e) 指定位置 → O(n)，因为需要先遍历到该位置
• addFirst()/addLast() → O(1)

Q4: LinkedList 是否线程安全？

答：LinkedList 不是线程安全的。多线程环境下可以使用：
• Collections.synchronizedList()
• ConcurrentLinkedDeque（无界并发队列）

Q5: LinkedList 能存 null 吗？

答：可以。LinkedList 允许存储 null 值，包括多个 null。这与某些队列实现不同（如 ArrayDeque 不允许 null）。

Q6: LinkedList 实现了哪些接口？

答：LinkedList 实现了多个接口：
• List - 有序集合操作
• Deque - 双端队列操作
• Queue - 队列操作
因此它既可以当列表用，也可以当栈/队列用。

Q7: 遍历 LinkedList 应该用什么方式？

答： • 推荐：Iterator 或 foreach（底层也是 Iterator）
• 避免：for + get(i)，因为每次 get 都要从头遍历，时间复杂度 O(n²)

Q8: LinkedList 的 Node 为什么是静态内部类？

答：使用静态内部类的原因：
• Node 不需要访问外部类实例
• 静态内部类不持有外部类引用，节省内存
• 避免内存泄漏风险
