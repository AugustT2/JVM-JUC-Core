💡 记忆技巧：可以想象成一个公司的招聘机制：

• corePoolSize = 正式员工数（永不裁员）

• maximumPoolSize = 公司最大容量（包含临时工）

• workQueue = 待办任务清单

• keepAliveTime = 临时工空闲多久被辞退

• handler = 任务太多处理不过来的应对方案

// 源码中的位运算常量 private static final int COUNT_BITS = Integer.SIZE - 3; // 29 private static final int COUNT_MASK = (1 << COUNT_BITS) - 1; // 0x1FFFFFFF // 线程池5种状态 private static final int RUNNING = -1 << COUNT_BITS; // 111 能接收任务，能处理队列任务 private static final int SHUTDOWN = 0 << COUNT_BITS; // 000 不接收新任务，但处理队列任务 private static final int STOP = 1 << COUNT_BITS; // 001 不接收，不处理，中断进行中 private static final int TIDYING = 2 << COUNT_BITS; // 010 所有任务终止，workerCount=0 private static final int TERMINATED = 3 << COUNT_BITS; // 011 terminated()执行完成 // 获取状态和线程数的方法 private static int runStateOf(int c) { return c & ~COUNT_MASK; } private static int workerCountOf(int c) { return c & COUNT_MASK; }

execute() 执行流程 最高频考点

public void execute(Runnable command) { if (command == null) throw new NullPointerException(); int c = ctl.get(); // Step 1: 如果工作线程数 < 核心线程数，创建核心线程 if (workerCountOf(c) < corePoolSize) { if (addWorker(command, true)) return; c = ctl.get(); } // Step 2: 核心线程已满，尝试加入队列 if (isRunning(c) && workQueue.offer(command)) { int recheck = ctl.get(); // 双重检查：如果线程池不在运行状态，移除任务并拒绝 if (!isRunning(recheck) && remove(command)) reject(command); // 如果没有工作线程了，创建一个非核心线程 else if (workerCountOf(recheck) == 0) addWorker(null, false); } // Step 3: 队列也满了，尝试创建非核心线程 else if (!addWorker(command, false)) // Step 4: 都失败了，执行拒绝策略 reject(command); }

Worker 工作机制 核心原理

Worker 是 ThreadPoolExecutor 的内部类，它实现了 Runnable 接口，同时继承了 AbstractQueuedSynchronizer (AQS)。每个 Worker 封装了一个线程和初始任务。

private final class Worker extends AbstractQueuedSynchronizer implements Runnable { final Thread thread; // Worker持有的线程 Runnable firstTask; // 初始任务，可能为null volatile long completedTasks; // 完成的任务数 Worker(Runnable firstTask) { setState(-1); // 禁止中断直到runWorker this.firstTask = firstTask; // 用ThreadFactory创建线程，传入Worker自身作为Runnable this.thread = getThreadFactory().newThread(this); } public void run() { runWorker(this); // 核心执行方法 } }

runWorker() - Worker的核心工作循环

final void runWorker(Worker w) { Thread wt = Thread.currentThread(); Runnable task = w.firstTask; w.firstTask = null; w.unlock(); // 允许中断 boolean completedAbruptly = true; try { // 🔄 核心循环：有初始任务就执行，没有就从队列取 while (task != null || (task = getTask()) != null) { w.lock(); // 获取Worker锁 // 检查线程池状态，必要时中断 if ((runStateAtLeast(ctl.get(), STOP) || (Thread.interrupted() && runStateAtLeast(ctl.get(), STOP))) && !wt.isInterrupted()) wt.interrupt(); try { beforeExecute(wt, task); // 钩子方法 try { task.run(); // 🎯 执行任务！ afterExecute(task, null); // 钩子方法 } catch (Throwable ex) { afterExecute(task, ex); throw ex; } } finally { task = null; w.completedTasks++; w.unlock(); } } completedAbruptly = false; } finally { processWorkerExit(w, completedAbruptly); } }

🔑 关键点：

1. Worker继承AQS实现不可重入的独占锁，用于判断线程是否空闲

2. firstTask可以为null，此时Worker创建后直接从队列获取任务

3. getTask()返回null时，Worker会退出循环并终止

4. beforeExecute/afterExecute是钩子方法，可以扩展自定义逻辑

四种拒绝策略 面试必考

当线程数达到maximumPoolSize且队列已满时，新提交的任务将被拒绝，此时会调用 RejectedExecutionHandler 的 rejectedExecution 方法。

AbortPolicy（默认）
直接抛出异常
抛出 RejectedExecutionException 异常，让调用者感知任务被拒绝，由调用者决定如何处理。
💥 throw RejectedExecutionException
CallerRunsPolicy
调用者线程执行
由提交任务的线程（调用execute的线程）自己执行该任务，实现简单的反压机制。
🔄 main线程自己执行任务
DiscardPolicy
静默丢弃
直接丢弃任务，不做任何处理也不抛异常。适用于可以接受任务丢失的场景。
🗑️ 任务被静默丢弃...
DiscardOldestPolicy
丢弃队头任务
丢弃队列中等待最久的任务（队头），然后尝试重新提交当前任务。
🔄 poll() 再 execute()

拒绝策略源码

// 1. AbortPolicy - 默认策略 public static class AbortPolicy implements RejectedExecutionHandler { public void rejectedExecution(Runnable r, ThreadPoolExecutor e) { throw new RejectedExecutionException("Task rejected"); } } // 2. CallerRunsPolicy - 调用者执行 public static class CallerRunsPolicy implements RejectedExecutionHandler { public void rejectedExecution(Runnable r, ThreadPoolExecutor e) { if (!e.isShutdown()) { r.run(); // 直接在调用者线程执行 } } } // 3. DiscardPolicy - 静默丢弃 public static class DiscardPolicy implements RejectedExecutionHandler { public void rejectedExecution(Runnable r, ThreadPoolExecutor e) { // 什么都不做，直接丢弃 } } // 4. DiscardOldestPolicy - 丢弃最旧任务 public static class DiscardOldestPolicy implements RejectedExecutionHandler { public void rejectedExecution(Runnable r, ThreadPoolExecutor e) { if (!e.isShutdown()) { e.getQueue().poll(); // 移除队头 e.execute(r); // 重新提交 } } }

💡 选择建议：

• AbortPolicy：要求任务不能丢失，需要上层处理异常

• CallerRunsPolicy：希望任务都执行，可接受调用者线程被阻塞

• DiscardPolicy：任务可丢弃，如日志采集等非关键任务

• DiscardOldestPolicy：新任务优先级更高的场景

线程复用原理 核心考点

线程池的核心优势就是线程复用，避免频繁创建/销毁线程带来的开销。关键在于 getTask() 方法的阻塞等待机制。

private Runnable getTask() { boolean timedOut = false; for (;;) { // 无限循环 int c = ctl.get(); int rs = runStateOf(c); // 检查线程池状态，决定是否退出 if (rs >= SHUTDOWN && (rs >= STOP || workQueue.isEmpty())) { decrementWorkerCount(); return null; // 返回null，Worker将退出 } int wc = workerCountOf(c); // 🔑 关键：是否需要超时控制 boolean timed = allowCoreThreadTimeOut || wc > corePoolSize; if ((wc > maximumPoolSize || (timed && timedOut)) && (wc > 1 || workQueue.isEmpty())) { if (compareAndDecrementWorkerCount(c)) return null; // 超时了，回收线程 continue; } try { // 🎯 线程复用的核心！ Runnable r = timed ? workQueue.poll(keepAliveTime, TimeUnit.NANOSECONDS) : // 超时等待 workQueue.take(); // 无限等待（核心线程） if (r != null) return r; timedOut = true; } catch (InterruptedException retry) { timedOut = false; } } }

🔑 线程复用的核心原理：

1. Worker线程不会在任务执行完后就销毁

2. 它会通过 getTask() 方法阻塞等待新任务

3. 核心线程调用 workQueue.take() 无限等待

4. 非核心线程调用 workQueue.poll(keepAliveTime) 超时等待

5. 超时后poll返回null，getTask返回null，Worker退出循环被回收

核心线程 vs 非核心线程

核心线程

  • 调用 take() 无限等待
  • 永远不会因超时被回收
  • 除非设置 allowCoreThreadTimeOut

非核心线程

  • 调用 poll(keepAliveTime)
  • 超时后返回null被回收
  • 用于处理突发流量
