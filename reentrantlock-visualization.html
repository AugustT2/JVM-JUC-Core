ReentrantLock 核心原理详解

1. AQS (AbstractQueuedSynchronizer) 核心机制

ReentrantLock 的底层实现依赖于 AQS，这是 Doug Lea 设计的一个用于构建锁和同步器的框架。

AQS 三大核心组件：
  • state：volatile int，表示同步状态。0 表示未锁定，≥1 表示已锁定（支持可重入）
  • exclusiveOwnerThread：记录当前持有锁的线程
  • CLH 队列：双向链表，存储等待获取锁的线程节点

2. 公平锁 vs 非公平锁

特性 公平锁 (FairSync) 非公平锁 (NonfairSync)
获取顺序 严格按照 FIFO 队列顺序 允许插队，新线程可直接尝试获取
吞吐量 较低 较高（减少线程切换）
饥饿问题 不会产生饥饿 可能导致某些线程长时间等待
默认选择 需显式指定 new ReentrantLock(true) 默认：new ReentrantLock()
// 非公平锁的 lock 方法 final void lock() { // 直接尝试 CAS 获取锁（插队） if (compareAndSetState(0, 1)) setExclusiveOwnerThread(Thread.currentThread()); else acquire(1); // 失败则走正常流程 } // 公平锁的 tryAcquire 方法 protected final boolean tryAcquire(int acquires) { // 必须检查队列中是否有前驱节点 if (!hasQueuedPredecessors() && compareAndSetState(0, acquires)) { setExclusiveOwnerThread(Thread.currentThread()); return true; } return false; }

3. 可重入实现原理

可重入锁允许同一线程多次获取同一把锁，避免死锁。实现关键在于 state 计数器：

final boolean nonfairTryAcquire(int acquires) { Thread current = Thread.currentThread(); int c = getState(); if (c == 0) { // 锁空闲，CAS 获取 if (compareAndSetState(0, acquires)) { setExclusiveOwnerThread(current); return true; } } else if (current == getExclusiveOwnerThread()) { // 可重入：同一线程再次获取，state + 1 int nextc = c + acquires; if (nextc < 0) // overflow throw new Error("Maximum lock count exceeded"); setState(nextc); return true; } return false; }
面试考点：为什么需要可重入？

如果锁不可重入，当同一线程在持有锁时调用另一个需要同一把锁的方法，就会产生死锁。例如：

synchronized void methodA() {
    methodB(); // 如果不可重入，这里会死锁
}
synchronized void methodB() {
    // ...
}

4. lock() 完整流程

  1. tryAcquire：尝试直接获取锁（CAS 设置 state）
  2. addWaiter：获取失败，将当前线程包装成 Node 加入 CLH 队列尾部
  3. acquireQueued：在队列中自旋，检查是否轮到自己
  4. shouldParkAfterFailedAcquire：设置前驱节点状态为 SIGNAL
  5. parkAndCheckInterrupt：调用 LockSupport.park() 阻塞线程
  6. 被唤醒后：继续自旋尝试获取锁

5. unlock() 完整流程

public void unlock() { sync.release(1); } protected final boolean tryRelease(int releases) { int c = getState() - releases; if (Thread.currentThread() != getExclusiveOwnerThread()) throw new IllegalMonitorStateException(); boolean free = false; if (c == 0) { // state 归零，真正释放锁 free = true; setExclusiveOwnerThread(null); } setState(c); // 可重入：state - 1 return free; } // 释放后唤醒后继节点 private void unparkSuccessor(Node node) { Node s = node.next; if (s != null) LockSupport.unpark(s.thread); }

6. 面试高频问题

Q1: ReentrantLock 和 synchronized 的区别？
特性 ReentrantLock synchronized
实现 JDK 层面（AQS） JVM 层面（monitor）

Q2: 为什么非公平锁性能更好？

非公平锁允许新到达的线程直接尝试获取锁，如果此时锁刚好释放，新线程可以直接获取， 避免了线程切换的开销。而公平锁必须唤醒队列中的线程，涉及到线程上下文切换， 这个过程需要操作系统介入，开销较大。

Q3: CLH 队列是什么？

CLH 队列是一个虚拟的双向队列（不存在真实的 Queue 对象），通过 Node 节点的 prev 和 next 指针连接。 AQS 维护了 head 和 tail 两个指针。head 是一个哑节点（dummy node），不存储线程信息， 真正等待的线程从 head.next 开始。
