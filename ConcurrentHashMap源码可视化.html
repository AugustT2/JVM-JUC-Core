JDK 7 分段锁机制

  • Segment[] 数组：继承 ReentrantLock
  • 锁粒度：锁整个 Segment
  • 并发度：受限于 Segment 数量（默认16）
  • 扩容：单个 Segment 独立扩容
  • 缺点：锁竞争集中，扩容不全局

JDK 8 CAS + synchronized

  • Node[] 数组：直接存储节点
  • 锁粒度：锁单个数组位置（桶）
  • 并发度：理论无限（取决于桶数量）
  • 扩容：多线程协助全局扩容
  • 优势：锁粒度更细，性能更高

📚 核心区别详解

1. 数据结构演变

// JDK7: Segment分段锁
static class Segment<K,V> extends ReentrantLock {
    transient volatile HashEntry<K,V>[] table;
    transient int count;
    // 锁住整个Segment，粒度较粗
}

// JDK8: 直接数组+CAS
transient volatile Node<K,V>[] table;
// 使用CAS+synchronized，锁粒度精确到单个桶
synchronized (f) {  // f是数组某个位置的头节点
    // 只锁定当前桶，其他桶可并发访问
}

2. 并发度提升

  • JDK7：并发度 = Segment数量（默认16），最多16个线程同时写入
  • JDK8：并发度 = 数组长度，理论可支持无限并发（不同桶）

3. 锁策略优化

  • 空桶插入：JDK8使用CAS无锁插入，JDK7需要获取Segment锁
  • 链表操作：JDK8只锁头节点，JDK7锁整个Segment
  • 红黑树：JDK8链表长度>8自动转换，查询O(log n)

📚 Put 流程详解

完整流程步骤

  1. 计算Hash：spread(key.hashCode())，高低位异或，减少碰撞
  2. 定位桶：(n - 1) & hash，快速取模找到数组位置
  3. 检查初始化：如果数组为null，调用initTable()初始化
  4. CAS插入：如果桶为空，使用CAS无锁插入新节点
  5. 帮助扩容：如果发现正在扩容(MOVED)，当前线程协助迁移
  6. 加锁插入：synchronized锁住头节点，遍历链表/红黑树插入
  7. 树化检查：链表长度 >= 8 且 数组长度 >= 64，转红黑树
  8. 计数增加：addCount()，LongAdder思想更新size

核心源码

final V putVal(K key, V value, boolean onlyIfAbsent) {
    int hash = spread(key.hashCode());  // 1. 计算hash

    for (Node<K,V>[] tab = table;;) {
        int n, i; Node<K,V> f;

        if (tab == null)
            tab = initTable();  // 2. 初始化
        else if ((f = tabAt(tab, i = (n - 1) & hash)) == null) {
            // 3. CAS插入空桶
            if (casTabAt(tab, i, null, new Node<>(hash, key, value)))
                break;  // 成功，无锁插入！
        }
        else if (f.hash == MOVED)
            tab = helpTransfer(tab, f);  // 4. 帮助扩容
        else {
            synchronized (f) {  // 5. 锁住头节点
                if (f instanceof Node) {
                    // 链表插入
                    for (Node<K,V> e = f; e != null; e = e.next) {
                        if (e.hash == hash && key.equals(e.key)) {
                            return e.val;  // key已存在
                        }
                        if (e.next == null) {
                            e.next = new Node<>(hash, key, value);
                            break;
                        }
                    }
                } else if (f instanceof TreeBin) {
                    // 红黑树插入
                }
            }
            // 6. 检查是否需要树化
            if (binCount >= TREEIFY_THRESHOLD)
                treeifyBin(tab, i);
        }
    }
    addCount(1L, binCount);  // 7. 计数+1
    return null;
}

关键优化点

  • 无锁快速路径：空桶CAS插入，避免加锁开销
  • 细粒度锁：只锁单个桶的头节点，不影响其他桶
  • 协助扩容：多线程共同完成扩容，提升吞吐量
  • 红黑树优化：解决hash碰撞严重时的性能退化

💡 扩容触发条件
  • 元素数量达到 0.75 * capacity（负载因子0.75）
  • 链表长度 >= 8 但数组长度 < 64 时，优先扩容而非树化
  • 扩容时容量翻倍：newCap = oldCap << 1

📚 扩容机制详解

1. 扩容流程

  1. 创建新数组：长度为原来的2倍
  2. 设置标志：sizeCtl设置为负数，表示正在扩容
  3. 分配任务：将旧数组分成多个区间，每个线程负责一段
  4. 数据迁移：
    • 锁住旧桶的头节点
    • 遍历链表/树，重新计算hash分配到新数组
    • 旧桶位置放置ForwardingNode(hash=-1)标记已迁移
  5. 协助扩容：其他线程发现MOVED节点，加入扩容队伍
  6. 完成扩容：所有桶迁移完毕，替换table引用

2. 核心源码

private final void transfer(Node<K,V>[] tab, Node<K,V>[] nextTab) {
    int n = tab.length, stride;

    // 计算每个线程负责的桶数量（最小16）
    if ((stride = (NCPU > 1) ? (n >>> 3) / NCPU : n) < MIN_TRANSFER_STRIDE)
        stride = MIN_TRANSFER_STRIDE;

    if (nextTab == null) {
        nextTab = new Node[n << 1];  // 创建2倍大小新数组
    }

    ForwardingNode<K,V> fwd = new ForwardingNode<>(nextTab);

    for (int i = 0; i < n; i++) {
        Node<K,V> f = tabAt(tab, i);

        if (f == null)
            casTabAt(tab, i, null, fwd);  // 空桶直接标记
        else {
            synchronized (f) {  // 锁住旧桶
                // 将节点重新分配到新数组
                // 根据 hash & oldCap 决定留在原位还是移到 i+oldCap
                Node<K,V> ln, hn;  // low/high链
                if (f.hash >= 0) {
                    int runBit = f.hash & n;
                    for (Node<K,V> p = f; p != null; p = p.next) {
                        // 分离节点到两条链表
                    }
                    setTabAt(nextTab, i, ln);        // 原位置
                    setTabAt(nextTab, i + n, hn);    // 原位置+oldCap
                }
                setTabAt(tab, i, fwd);  // 标记迁移完成
            }
        }
    }
}

3. 协助扩容机制

final Node<K,V>[] helpTransfer(Node<K,V>[] tab, Node<K,V> f) {
    Node<K,V>[] nextTab;

    if (f instanceof ForwardingNode) {
        nextTab = ((ForwardingNode<K,V>)f).nextTable;

        // 尝试加入扩容队伍
        if (nextTab != null) {
            int sc;
            while (扩容未完成 && sizeCtl < 0) {
                // CAS增加扩容线程计数
                if (U.compareAndSwapInt(this, SIZECTL, sc, sc + 1)) {
                    transfer(tab, nextTab);  // 参与迁移工作
                    break;
                }
            }
            return nextTab;
        }
    }
    return table;
}

4. 关键优化

  • 多线程并行：将数组分段，多个线程同时迁移不同区间
  • 主动协助：Put/Get时遇到MOVED节点会主动帮助扩容
  • 位运算优化：通过 hash & oldCap 快速判断新位置
  • ForwardingNode：标记已迁移桶，并提供查询转发功能

💡 为什么不用 AtomicLong？

高并发环境下，大量线程CAS更新同一个AtomicLong会导致严重的竞争和自旋，性能急剧下降。

LongAdder思想：将热点分散到多个Cell，减少竞争，最后汇总得到总数。

📚 计数机制详解

1. 数据结构

private transient volatile long baseCount;  // 基础计数

private transient volatile CounterCell[] counterCells;  // 计数单元数组

// 计数单元（使用@Contended避免伪共享）
@sun.misc.Contended static final class CounterCell {
    volatile long value;
    CounterCell(long x) { value = x; }
}

2. 计数流程

  1. 低竞争：直接CAS更新baseCount
  2. CAS失败：说明存在竞争，尝试更新CounterCell
  3. Cell选择：通过线程ID随机选择一个Cell，ThreadLocalRandom.probe()
  4. Cell扩容：如果Cell也竞争激烈，扩容Cell数组（最大CPU核数）
  5. 获取总数：sum = baseCount + Σ(counterCells[i].value)

3. addCount 核心源码

private final void addCount(long x, int check) {
    CounterCell[] as; long b, s;

    // 尝试直接CAS更新baseCount
    if ((as = counterCells) != null ||
        !U.compareAndSwapLong(this, BASECOUNT, b = baseCount, s = b + x)) {

        // baseCount更新失败，使用CounterCell
        CounterCell a; long v; int m;
        boolean uncontended = true;

        if (as == null || (m = as.length - 1) < 0 ||
            (a = as[ThreadLocalRandom.getProbe() & m]) == null ||
            !(uncontended = U.compareAndSwapLong(a, CELLVALUE, v = a.value, v + x))) {

            // Cell也失败，进入fullAddCount处理
            fullAddCount(x, uncontended);
            return;
        }
    }

    // 检查是否需要扩容
    if (check >= 0) {
        if (s >= (long)(sc = sizeCtl) && table != null) {
            transfer(table, null);  // 触发扩容
        }
    }
}

4. 获取总数

public long size() {
    long n = sumCount();
    return (n < 0L) ? 0L : n;
}

final long sumCount() {
    CounterCell[] as = counterCells;
    long sum = baseCount;  // 从baseCount开始

    if (as != null) {
        for (int i = 0; i < as.length; i++) {
            CounterCell a;
            if ((a = as[i]) != null)
                sum += a.value;  // 累加所有Cell
        }
    }
    return sum;  // 注意：非强一致性，是近似值
}

5. 关键点总结

  • 热点分散：多个Cell分担压力，避免单点竞争
  • 动态扩容：Cell数组根据竞争情况动态扩容
  • 伪共享优化：@Contended注解保证Cell不在同一缓存行
  • 弱一致性：size()返回的是近似值，不保证强一致性
  • 空间换时间：牺牲少量空间（Cell数组），换取高并发性能

6. 性能对比

AtomicLong

  • 单个热点变量
  • 高并发下CAS自旋严重
  • 线程数增加，性能急剧下降
  • 适合低并发场景

LongAdder

  • 多个Cell分散热点
  • 减少CAS竞争
  • 线程数增加，性能线性扩展
  • 适合高并发计数场景
