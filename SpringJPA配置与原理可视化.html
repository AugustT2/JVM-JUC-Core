ddl-auto 配置说明

  • create: 每次启动删除并创建新表
  • create-drop: 启动时创建，关闭时删除
  • update: 更新表结构（推荐开发环境）
  • validate: 验证表结构，不修改
  • none: 不做任何操作（推荐生产环境）

3. Entity 实体类定义

import javax.persistence.*;
import lombok.Data;
import java.time.LocalDateTime;

@Data
@Entity  // 标记为JPA实体
@Table(name = "users")  // 指定表名
public class User {

    @Id  // 主键
    @GeneratedValue(strategy = GenerationType.IDENTITY)  // 自增策略
    private Long id;

    @Column(name = "username", nullable = false, unique = true, length = 50)
    private String username;

    @Column(nullable = false)
    private String password;

    @Column(length = 100)
    private String email;

    @Column(name = "create_time")
    private LocalDateTime createTime;

    @Column(name = "update_time")
    private LocalDateTime updateTime;

    // 一对多关联
    @OneToMany(mappedBy = "user", cascade = CascadeType.ALL)
    private List<Order> orders;

    @PrePersist  // 保存前自动设置创建时间
    protected void onCreate() {
        createTime = LocalDateTime.now();
    }

    @PreUpdate  // 更新前自动设置更新时间
    protected void onUpdate() {
        updateTime = LocalDateTime.now();
    }
}

常用注解说明

类级别注解

  • @Entity: 标记为JPA实体
  • @Table: 指定表名和索引
  • @EntityListeners: 实体监听器

字段级别注解

  • @Id: 主键标识
  • @GeneratedValue: 主键生成策略
  • @Column: 列定义
  • @Transient: 不持久化

4. Repository 接口定义

import org.springframework.data.jpa.repository.*;
import org.springframework.data.repository.query.Param;
import java.util.List;

public interface UserRepository extends JpaRepository<User, Long> {

    // 1. 方法名查询（自动解析）
    User findByUsername(String username);

    List<User> findByEmailContaining(String email);

    List<User> findByCreateTimeBetween(LocalDateTime start, LocalDateTime end);

    // 2. @Query JPQL查询
    @Query("SELECT u FROM User u WHERE u.username = :username")
    User findUserByUsername(@Param("username") String username);

    // 3. 原生SQL查询
    @Query(value = "SELECT * FROM users WHERE email = ?1", nativeQuery = true)
    User findByEmailNative(String email);

    // 4. 更新操作
    @Modifying
    @Query("UPDATE User u SET u.email = :email WHERE u.id = :id")
    int updateEmail(@Param("id") Long id, @Param("email") String email);

    // 5. 分页查询
    Page<User> findByEmailContaining(String email, Pageable pageable);
}

Repository 接口层次

  • Repository: 标记接口，无方法
  • CrudRepository: 基本CRUD操作
  • PagingAndSortingRepository: 添加分页和排序
  • JpaRepository: 添加JPA特有功能（批量操作等）

5. Service 层使用

import org.springframework.stereotype.Service;
import org.springframework.transaction.annotation.Transactional;
import lombok.RequiredArgsConstructor;

@Service
@RequiredArgsConstructor  // Lombok生成构造器注入
public class UserService {

    private final UserRepository userRepository;

    // 查询操作
    public User getUserById(Long id) {
        return userRepository.findById(id)
            .orElseThrow(() -> new RuntimeException("User not found"));
    }

    // 保存操作（带事务）
    @Transactional
    public User createUser(User user) {
        return userRepository.save(user);
    }

    // 更新操作
    @Transactional
    public User updateUser(Long id, User userDetails) {
        User user = getUserById(id);
        user.setUsername(userDetails.getUsername());
        user.setEmail(userDetails.getEmail());
        return userRepository.save(user);
    }

    // 删除操作
    @Transactional
    public void deleteUser(Long id) {
        userRepository.deleteById(id);
    }

    // 分页查询
    public Page<User> getUsersByEmail(String email, int page, int size) {
        Pageable pageable = PageRequest.of(page, size, Sort.by("createTime").descending());
        return userRepository.findByEmailContaining(email, pageable);
    }
}

Spring Data JPA 架构层次

应用层 (Application Layer)

Controller / Service - 业务逻辑层，调用Repository接口完成数据操作

↓

Spring Data JPA 层

Repository 接口代理 - Spring动态生成实现类，解析方法名或@Query注解

核心组件：SimpleJpaRepository（默认实现）、RepositoryFactorySupport、QueryLookupStrategy

↓

JPA 规范层 (API)

EntityManager / EntityManagerFactory - JPA标准API，定义持久化操作规范

核心接口：EntityManager.persist(), find(), merge(), remove()

↓

Hibernate 实现层

SessionFactory / Session - JPA规范的Hibernate实现

功能：对象关系映射（ORM）、SQL生成、缓存管理、延迟加载

↓

JDBC 层

DataSource / Connection - 数据库连接管理，执行原生SQL

HikariCP连接池、PreparedStatement执行SQL

↓

数据库层 (Database)

MySQL / PostgreSQL / Oracle - 实际的数据存储

层次关系说明

  • JPA 是规范：定义了接口标准（javax.persistence包），不是实现
  • Hibernate 是实现：JPA规范最流行的实现框架
  • Spring Data JPA：在JPA之上的封装，简化Repository开发
  • 依赖关系：Spring Data JPA → JPA API → Hibernate → JDBC → Database
  • 可替换性：可以将Hibernate替换为EclipseLink等其他JPA实现

流程步骤详解

  1. 步骤1 - Service调用Repository方法： userRepository.findByUsername("john")
    Service层通过依赖注入获取到的Repository接口实例（实际是代理对象）
  2. 步骤2 - JDK动态代理拦截： Spring通过JDK动态代理（或CGLIB）拦截方法调用，代理对象并非真实的Repository实现
  3. 步骤3 - 方法名解析： QueryLookupStrategy解析方法名"findByUsername"，识别查询类型（查找）和条件（username字段）
  4. 步骤4 - 生成JPQL/HQL查询： 根据解析结果生成JPQL：SELECT u FROM User u WHERE u.username = ?1
  5. 步骤5 - Hibernate翻译为SQL： Hibernate将JPQL翻译成数据库特定的SQL：SELECT * FROM users WHERE username = ?
  6. 步骤6 - JDBC执行并返回结果： 通过JDBC执行SQL，获取ResultSet，Hibernate映射为Entity对象返回

Repository 代理机制原理

代理创建过程

  1. 1. Spring容器启动扫描： @EnableJpaRepositories注解触发，扫描所有继承Repository的接口
  2. 2. RepositoryFactorySupport创建代理： 
    public class JpaRepositoryFactory extends RepositoryFactorySupport {
    protected Object getTargetRepository(RepositoryInformation info) {
        // 创建SimpleJpaRepository实例作为目标对象
        return new SimpleJpaRepository<>(entityInfo, entityManager);
    }

    protected Class<?> getRepositoryBaseClass(RepositoryMetadata metadata) {
        return SimpleJpaRepository.class;
    }
}
  3. 3. JDK动态代理生成实现类： 
    // Spring内部使用类似逻辑
Object proxy = Proxy.newProxyInstance(
    classLoader,
    new Class[] { UserRepository.class },
    new InvocationHandler() {
        public Object invoke(Object proxy, Method method, Object[] args) {
            // 1. 判断方法类型（CRUD、自定义查询、@Query）
            if (isCrudMethod(method)) {
                return simpleJpaRepository.invoke(method, args);
            }
            // 2. 解析方法名查询
            if (isQueryMethod(method)) {
                Query query = parseMethodName(method);
                return query.execute(args);
            }
            // 3. 处理@Query注解
            if (hasQueryAnnotation(method)) {
                return executeQueryAnnotation(method, args);
            }
        }
    }
);
  4. 4. 注册到Spring容器： 代理对象以Bean的形式注册到Spring容器，可通过@Autowired注入

SimpleJpaRepository 默认实现

@Repository
@Transactional(readOnly = true)
public class SimpleJpaRepository<T, ID> implements JpaRepository<T, ID> {

    private final EntityManager em;
    private final JpaEntityInformation<T, ?> entityInformation;

    @Transactional
    public <S extends T> S save(S entity) {
        if (entityInformation.isNew(entity)) {
            em.persist(entity);  // 新实体：插入
            return entity;
        } else {
            return em.merge(entity);  // 已存在：更新
        }
    }

    public Optional<T> findById(ID id) {
        return Optional.ofNullable(em.find(entityInformation.getJavaType(), id));
    }

    @Transactional
    public void delete(T entity) {
        em.remove(em.contains(entity) ? entity : em.merge(entity));
    }
}

方法名解析查询原理

方法名解析规则

解析器：PartTree 类

Spring Data JPA使用PartTree类解析方法名，将其拆分为查询主语（Subject）和谓词（Predicate）

方法名组成结构

查询主语 + By + 条件属性 + 条件关键字 + 连接词 + 排序

示例：findDistinctUserByUsernameAndEmailOrderByCreateTimeDesc

拆解：
- find: 查询主语（返回类型）
- Distinct: 去重
- User: 可选的实体名称
- By: 分隔符
- Username: 第一个条件属性
- And: 连接词
- Email: 第二个条件属性
- OrderBy: 排序关键字
- CreateTime: 排序字段
- Desc: 降序

支持的查询关键字

查询主语

  • find...By / read...By / get...By / query...By: 查询
  • count...By: 统计数量
  • exists...By: 判断是否存在
  • delete...By / remove...By: 删除

条件关键字

  • And / Or: 逻辑连接
  • Is / Equals: 相等
  • Between: 区间
  • LessThan / GreaterThan: 大小比较
  • Like / NotLike: 模糊查询
  • StartingWith / EndingWith / Containing: 字符串匹配
  • In / NotIn: 集合包含
  • IsNull / IsNotNull: 空值判断
  • True / False: 布尔值

方法名示例

// 1. 简单查询
User findByUsername(String username);
→ SELECT u FROM User u WHERE u.username = ?1

// 2. 多条件AND
List<User> findByUsernameAndEmail(String username, String email);
→ SELECT u FROM User u WHERE u.username = ?1 AND u.email = ?2

// 3. 模糊查询
List<User> findByUsernameLike(String pattern);
→ SELECT u FROM User u WHERE u.username LIKE ?1

// 4. 区间查询
List<User> findByCreateTimeBetween(LocalDateTime start, LocalDateTime end);
→ SELECT u FROM User u WHERE u.createTime BETWEEN ?1 AND ?2

// 5. 排序
List<User> findByEmailOrderByCreateTimeDesc(String email);
→ SELECT u FROM User u WHERE u.email = ?1 ORDER BY u.createTime DESC

// 6. 统计
long countByEmail(String email);
→ SELECT COUNT(u) FROM User u WHERE u.email = ?1

// 7. 删除
long deleteByUsername(String username);
→ DELETE FROM User u WHERE u.username = ?1

// 8. IN查询
List<User> findByIdIn(List<Long> ids);
→ SELECT u FROM User u WHERE u.id IN ?1

// 9. 关联查询
List<Order> findByUser_Username(String username);
→ SELECT o FROM Order o WHERE o.user.username = ?1

解析流程源码

public class PartTree {
    public PartTree(String source, Class<?> domainClass) {
        // 1. 按"By"分割方法名
        Matcher matcher = PREFIX_TEMPLATE.matcher(source);
        if (!matcher.find()) {
            throw new IllegalArgumentException("Invalid method name");
        }

        // 2. 解析查询主语（find、count、delete等）
        this.subject = new Subject(matcher.group(0));

        // 3. 解析谓词条件
        this.predicate = new Predicate(source.substring(matcher.end()), domainClass);
    }

    // 将解析结果转换为JPQL查询
    public Query createQuery(EntityManager em) {
        StringBuilder jpql = new StringBuilder("SELECT ");
        jpql.append(subject.isDistinct() ? "DISTINCT " : "");
        jpql.append("e FROM ").append(domainClass.getSimpleName()).append(" e");

        if (predicate.hasConditions()) {
            jpql.append(" WHERE ").append(predicate.toJpql());
        }

        return em.createQuery(jpql.toString());
    }
}

Spring JPA 事务管理机制

事务传播机制

@Transactional(propagation = Propagation.REQUIRED)
public void method() {
    // 事务行为取决于传播级别
}

常用传播级别

  • REQUIRED（默认）: 有事务则加入，无则新建
  • REQUIRES_NEW: 总是新建事务，挂起当前事务
  • SUPPORTS: 有事务则加入，无则非事务执行
  • NOT_SUPPORTED: 非事务执行，挂起当前事务
  • MANDATORY: 必须在事务中，否则抛异常
  • NEVER: 不能在事务中，否则抛异常
  • NESTED: 嵌套事务（需数据库支持）

隔离级别

  • DEFAULT: 使用数据库默认级别
  • READ_UNCOMMITTED: 读未提交
  • READ_COMMITTED: 读已提交
  • REPEATABLE_READ: 可重复读
  • SERIALIZABLE: 串行化

事务注解详解

@Transactional(
    propagation = Propagation.REQUIRED,        // 传播行为
    isolation = Isolation.DEFAULT,              // 隔离级别
    timeout = 30,                                 // 超时时间（秒）
    readOnly = false,                           // 只读事务
    rollbackFor = Exception.class,              // 回滚异常类型
    noRollbackFor = IllegalArgumentException.class  // 不回滚的异常
)
public void complexOperation() {
    // 业务逻辑
}

SimpleJpaRepository 的事务配置

@Repository
@Transactional(readOnly = true)  // 类级别：所有方法默认只读
public class SimpleJpaRepository<T, ID> {

    // 查询方法继承类级别的只读事务
    public Optional<T> findById(ID id) {
        return Optional.ofNullable(em.find(entityClass, id));
    }

    // 写操作覆盖为读写事务
    @Transactional  // readOnly = false
    public <S extends T> S save(S entity) {
        if (isNew(entity)) {
            em.persist(entity);
            return entity;
        } else {
            return em.merge(entity);
        }
    }

    @Transactional
    public void delete(T entity) {
        em.remove(em.contains(entity) ? entity : em.merge(entity));
    }
}

事务实现原理

AOP代理机制

Spring使用AOP（面向切面编程）实现声明式事务管理：

  1. 为带@Transactional的类创建代理对象
  2. 调用方法时，代理拦截器先开启事务
  3. 执行目标方法
  4. 方法正常结束则提交事务，抛异常则回滚
// Spring内部事务拦截器伪代码
public class TransactionInterceptor {
    public Object invoke(MethodInvocation invocation) {
        TransactionInfo txInfo = createTransactionIfNecessary();
        Object retVal = null;
        try {
            // 执行目标方法
            retVal = invocation.proceed();
            // 提交事务
            commitTransactionAfterReturning(txInfo);
        } catch (Throwable ex) {
            // 回滚事务
            completeTransactionAfterThrowing(txInfo, ex);
            throw ex;
        } finally {
            cleanupTransactionInfo(txInfo);
        }
        return retVal;
    }
}

常见事务失效场景

注意避免

  • 同类内部调用：方法A调用同类的方法B，B的@Transactional失效（没走代理）
  • 方法非public：@Transactional只对public方法有效
  • 异常被捕获：异常被catch住未抛出，事务不会回滚
  • 异常类型不匹配：默认只回滚RuntimeException，检查异常不回滚
  • 数据库不支持：MyISAM引擎不支持事务，需使用InnoDB

正确使用示例

@Service
public class UserService {

    @Autowired
    private UserRepository userRepository;

    @Autowired
    private OrderRepository orderRepository;

    // 正确：在Service层使用@Transactional
    @Transactional(rollbackFor = Exception.class)
    public void createUserWithOrder(User user, Order order) {
        userRepository.save(user);  // Repository自带的事务会加入当前事务
        order.setUser(user);
        orderRepository.save(order);

        // 任何异常都会导致整体回滚
        if (someCondition) {
            throw new BusinessException("回滚事务");
        }
    }

    // 错误示例：内部调用不走代理
    public void publicMethod() {
        this.transactionalMethod();  // 事务失效！
    }

    @Transactional
    private void transactionalMethod() {
        // 不会在事务中执行
    }
}
